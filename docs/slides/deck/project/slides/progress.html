6 · Built and checked so far

The measurement setup is built and verified

Emulator is accurate

Delay within 0.4 ms, speed within 0.2%, buffer 200 ± 1 ms. Checking caught two emulator bugs, now fixed.

Multipath works

20 of 20 test transfers used both links (each 49–51% of the data).

Protocol fixes

Four small changes to the QUIC library, each with a test, incl. a connection-stall bug in the library itself.

Pipeline

Video streamer, one-command runs, scoring and statistics code, all tested.

Calibration: delay measured by ping, speed by flooding each link with UDP and counting bytes per 100 ms. Two problems found: the standard Linux shaper (tbf) refills its tokens on every rate change and delivered 9 to 25 percent too much during trace replay; and an 8 kbit/s stand-in for "zero" left the shaper owing 1.2 s of tokens. Both fixed (htb plus a plug queue). TQUIC changes: a fix for a stall where a link waiting for validation blocked all links (a real bug in TQUIC 1.6.0); letting a frame be pinned to a link; letting a scheduler wait for a faster link; and stopping CUBIC from growing its window when the video does not use it (RFC 9002 section 7.8). Our first version of that last change froze the sending rate after outages; the first runs showed it, we fixed it with a test and reran everything. The QUIC library's 565 tests pass.
